# 메타데이터 규격

이 규격은 이 저장소의 실제 렌더링 코드에서 도출한 것이다. 코드가 바뀌면 이 파일도 갱신해야 한다 (근거 파일: `src/utilities/generateMeta.ts`, `src/app/(frontend)/cases/page.tsx`).

## title (본문 제목, h1)

- 형태: `[사건 유형·죄명] [핵심 결과]` + 필요시 짧은 맥락. 예: `아동복지법위반(아동학대·금품유용) 혐의없음 처분 사례`
- 길이: 25~40자 목표. 검색 결과에서 잘리는 것보다 검색어 매칭이 우선.
- 잠재 의뢰인이 실제로 입력할 검색어(죄명 + "무혐의", "집행유예", "감형" 등)가 앞쪽에 오게.
- 금지: "이끌어내다", "~한 이유", "충격" 등 블로그식 낚시 어투. 이모지. 특수문자 남발.

## slug

- 영문 kebab-case, 3~6단어. 죄명-결과 순. 예: `child-welfare-no-suspicion`, `fraud-appeal-fine-reduction`
- 절대 금지: 한글, 공백, 슬래시(`/`), 후행 공백. 슬래시가 들어가면 `[slug]` 라우트와 매칭되지 않아 페이지가 열리지 않는다.
- `findCases`의 `where: {"slug": {"equals": "<candidate>"}}`로 중복 확인 후 확정.
- 저장 시 `generateSlug: false` 필수 (SKILL.md 6단계 참조).

## meta.title

- 프론트(`generateMeta.ts`)가 뒤에 `" | 법무법인 인유 창원분사무소"`(약 15자)를 자동으로 붙인다. **사무소명을 직접 넣지 말 것.**
- 따라서 meta.title 자체는 20~28자 목표 (전체 45자 내외).
- 본문 title과 같아도 되고, title이 길면 검색어 중심으로 축약한 버전을 쓴다.

## meta.description

- 70~110자. 모바일 SERP에서 앞 80자 정도가 노출되므로 핵심(죄명→결과)을 앞에.
- 구성: 어떤 혐의/사건 → 어떤 대응 → 어떤 결과. 마지막에 사무소·변호사 언급 가능.
- 사이트 내 검색(`/cases` 목록의 검색창)이 title·meta.title·meta.description을 like 검색하므로, 여기 넣은 키워드는 사이트 내 검색에도 잡힌다.
- 광고규정 준수: 결과 보장 암시 금지. 이 사건의 결과를 사실로 서술하는 것은 가능.

## meta.image

- `heroImage`와 같은 media id를 넣는다. 현재 프론트 OG 태그는 이 값을 쓰지 않지만(알려진 코드 이슈, 별도 수정 예정), 데이터는 채워 둔다.

## 키워드 원칙

- 1글 1주제: 주력 검색 의도 하나(예: "아동학대 무혐의")를 title·meta.title·meta.description·h2·본문 첫 문단에 일관되게.
- 지역 키워드("창원", "경남")는 사무소 소개 맥락에서 자연스럽게만. 사건 관할을 왜곡하면서까지 넣지 않는다.
- 키워드 반복 채우기(stuffing) 금지 — 같은 표현이 본문에 부자연스럽게 반복되면 실패.
